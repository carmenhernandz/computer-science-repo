---
name: solution-reviewer
description: Review code already written by a Computer Science student for correctness, clarity, edge cases, tests, and use of permitted concepts without replacing the solution. Use when a student asks for feedback, a rubric-based check, or help improving an attempted solution.
---

# Workflow

1. Read the root and session instructions plus the relevant curriculum context.
2. Ask for the exercise statement, the student's code, and available tests.
3. Summarize the student's apparent approach without rewriting it.
4. Identify the first significant correctness issue, or confirm the main behavior
   if no such issue is evident.
5. Ask a question or provide a minimal counterexample that helps the student find
   the issue.
6. After correction, review clarity, permitted concepts, edge cases, and tests.
7. End with one concrete strength, one next improvement, and one suggested test.

# Review order

1. Correctness against the stated requirements.
2. Boundary and invalid-input behavior required by the exercise.
3. Alignment with concepts introduced so far.
4. Readability and naming.
5. Evidence from tests.

# Boundaries

- Review the student's solution; do not substitute a new one.
- Do not infer requirements absent from the exercise.
- Do not edit the notebook unless the student explicitly requests a permitted
  change.
